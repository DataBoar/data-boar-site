Ecosystem de composição

Um ecossistema de plugins independentes.

Bestials conectadas via SDK. Sem runtime monolítico. Superpoderes explícitos.

O Data Boar Ecosystem é uma arquitetura de composição: cada Bestial é um plugin/sidecar independente que se comunica via contrato SDK. Você escolhe as ferramentas que precisa — não é forçado usar tudo.

Ver o código no GitHub → Agendar demonstração

Visão geral da arquitetura

Não é um produto monolítico. É um ecossistema de plugins separados.

Composable by design

Cada Bestial é um plugin/sidecar com escopo definido. Elas se conectam via SDK — não via chamar código interno. Você pode usar apenas as que precisa.

Superpoderes explícitos

Cada Bestial tem uma responsabilidade única e documentada. Você sabe exatamente o que cada plugin faz — e o que NÃO faz.

Fronteiras claras

Limits de dados, autorização, retenção e egress são definidos por contrato. Nenhum plugin decide sobre dados que não autorizou explicitamente.

Auditável por design

Todos os plugins seguem o mesmo padrão de contrato. Você pode auditorizar o comportamento de cada um separadamente.

As Bestials: Superpoderes do ecossistema

Cada uma tem uma missão clara. Nenhuma é obrigatória.

Sage Remora (Sage)

Superpoder: Análise de risco de reidentificação sem tocar dados. Lê manifestos de achados e infere risco de cruzamento de identificadores indiretos.

Maturidade: Em desenvolvimento/PoC

Contrato: SDK Manifesto L1

Faithful Ferret (Ferret)

Superpoder: Mede k-anonimato sobre dados autorizados. Garante que grupos de registros não podem ser re-identificados.

Maturidade: Demo/PoC

Contrato: SDK Transformado L3

Stealthy Stoat (Stoat)

Superpoder: Tokenização FF1 (NIST SP 800-38G). Substitui valores sensíveis por tokens reversíveis controlados.

Maturidade: Demo/PoC

Contrato: SDK Transformado L3

Keen Platypus (Platypus)

Superpoder: DevSecOps local: varredura de vulnerabilidades e código. Detecta riscos na cadeia de suprimentos.

Maturidade: Em desenvolvimento

Contrato: SDK

Fluxo típico: Boar → Sage → Ferret. A Sage também alimenta o Stoat (boar | sage > stoat).

Como funciona a comunicação

SDK como contrato único para todos os plugins.

Manifesto de achados (L1)

Primeiro patamar: metadados estruturados sobre o que foi encontrado. Nunca valores brutos.

Transformação governada (L3)

Terceiro patamar: dados transformados com scope de permissão explícita. Sempre auditável.

Saídas verificáveis

Cada plugin produz evidências técnicas para uma pessoa decidir — não um veredito automático.

Leia o código antes de confiar nele.

É open-core: audite, rode local e veja por que a evidência é reprodutível.

Overview of the architecture

This is not a monolithic product. It's an ecosystem of separate plugins.

Composable by design

Each Bestial is an independent plugin/sidecar with defined scope. They connect via SDK — not via internal code calls. Use only the tools you need.

Explicit superpowers

Each Bestial has a unique, documented responsibility. You know exactly what each plugin does — and what it does NOT do.

Clear boundaries

Data limits, authorization, retention and egress are defined by contract. No plugin decides on data that was not explicitly authorized.

Auditable by design

All plugins follow the same contract pattern. You can audit each one's behavior separately.

The Bestials: Ecosystem superpowers

Each has a clear mission. None is mandatory.

Sage Remora (Sage)

Power: Re-identification risk analysis without touching data. Reads finding manifests and infers risk of indirect identifier cross-over.

Maturity: Development/PoC

Contract: L1 Manifest SDK

Faithful Ferret (Ferret)

Power: Measures k-anonymity on authorized data. Ensures record groups cannot be re-identified.

Maturity: Demo/PoC

Contract: L3 Transformed SDK

Stealthy Stoat (Stoat)

Power: FF1 tokenization (NIST SP 800-38G). Replaces sensitive values with controlled reversible tokens.

Maturity: Demo/PoC

Contract: L3 Transformed SDK

Keen Platypus (Platypus)

Power: Local DevSecOps: vulnerability scanning and code. Detects supply chain risks.

Maturity: Development

Contract: SDK

Typical flow: Boar → Sage → Ferret. Sage also feeds Stoat (boar | sage > stoat).

How plugins communicate

SDK as single contract for all plugins.

Finding manifest (L1)

First tier: structured metadata about what was found. Never raw values.

Governed transformation (L3)

Third tier: transformed data with explicit permission scope. Always auditable.

Verifiable outputs

Each plugin produces technical evidence for a person to decide — not an automated verdict.

Read the code before you trust it.

It is open-core: audit it, run it locally, and see why the evidence is reproducible.
