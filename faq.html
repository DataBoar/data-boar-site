Inventário e LGPD

O que é inventário de dados pessoais na LGPD?

É o registro de quais dados pessoais a organização trata, onde estão, para quê, com qual base legal, quem acessa e por quanto tempo. A LGPD (art. 37) exige que controlador e operador mantenham registro das operações de tratamento. Sem inventário fica difícil atender titulares, elaborar RIPD ou demonstrar conformidade em fiscalização.

Inventário (ROPA) e descoberta técnica são a mesma coisa?

Não. O inventário/ROPA é o documento de governança (finalidade, base legal, responsáveis). A descoberta técnica responde: “em qual pasta, planilha ou sistema esse CPF realmente aparece?”. Os dois se complementam. Planilha da ANPD ajuda no registro administrativo; não substitui varrer o disco atrás de arquivo esquecido.

DataBoar substitui DPO-as-a-Service ou plataforma de mapeamento por autodeclaração?

Não — são categorias diferentes. Serviços e plataformas de “DPO terceirizado” / mapeamento por autodeclaração costumam registrar o que a organização declara sobre processos e rotinas (em muitos casos o arquivo do cliente não entra na plataforma). O DataBoar faz descoberta técnica local: procura onde o dado aparece de fato em pastas e arquivos e gera evidência de inventário e triagem. Os dois podem se complementar; um não substitui o outro. Continua não sendo parecer jurídico nem selo de conformidade.

Como descobrir onde estão os dados pessoais da minha empresa?

Além de conversar com as áreas e preencher planilhas, dá para automatizar: varrer pastas e arquivos (PDF, Excel, Word, ZIP) e, quando configurado, bancos e sistemas, identificando CPF, e-mail, dados bancários e outros padrões brasileiros. O DataBoar faz isso de forma local (nada sai do seu ambiente) e entrega relatório em Excel com os caminhos dos achados.

Para quem é / o que preciso saber

Preciso ser de TI ou ter DPO para usar?

Não necessariamente. Existe caminho pensado para quem nunca usou terminal — ver Data Boar no Windows (sem Docker). Microempresas e profissionais liberais muitas vezes não são obrigados a nomear DPO (Resolução CD/ANPD nº 2/2022), conforme o perfil de risco. O DataBoar gera evidência técnica; a decisão de conformidade continua sendo do responsável pela organização — não é parecer jurídico.

Serve para escritório de contabilidade?

Sim. Contabilidades tratam CPF, IR, folha, dados bancários por obrigação legal. O risco prático costuma ser arquivo solto, pasta compartilhada demais ou ex-cliente antigo. A descoberta ajuda a enxergar onde isso está; organizar, restringir acesso ou eliminar o que já passou do prazo legal continua sendo trabalho do escritório.

Privacidade e modelo local

O DataBoar envia meus dados para a nuvem?

Não. O desenho é local-first: a varredura roda no seu ambiente. O que se produz são metadados e relatórios de achados — o conteúdo dos documentos dos clientes não é enviado a servidores de terceiros.

É open source e auditável?

Sim. O código do núcleo está público no GitHub. Dá para inspecionar como a detecção e os logs funcionam. Modelo open-core: base gratuita e aberta; suporte, SLA e recursos avançados para cenários corporativos maiores podem ser comerciais.

Instalação e uso prático

Preciso instalar Docker?

Não. Docker é opção para quem já vive de contêiner. No Windows o caminho recomendado para não-técnicos é nativo (Python + demo), descrito em windows.html.

Como começar sem medo de quebrar o computador?

Comece sempre pelo modo demo:

data-boar --demo

Usa só dados sintéticos (de mentira) e abre o painel em http://127.0.0.1:8088. Nada dos seus arquivos reais é lido. Só depois de validar, aponte para uma pasta de teste — e só então para pastas reais.

Funciona com ZIP e arquivos com senha?

ZIP: sim — o conteúdo interno pode ser analisado sem descompactar tudo na mão.
Com senha: não — nenhum software legítimo “adivinha” o conteúdo; o relatório indica que a leitura foi bloqueada, para você saber o que já está trancado.

Em computador antigo demora muito?

Não, se você apontar só a pasta de clientes ou documentos de trabalho — não mande varrer o disco inteiro (C:\). Assim a varredura costuma levar minutos, não a noite toda — e continua offline durante a análise.

Dados de menores / LGPD Art. 14

Guia completo (GEO/AEO): Como evidenciar dados de menores em pastas sem programar.

Como descubro dados de menores nas minhas pastas sem programar?

Aponte pastas e exports (matrícula, LMS, planilhas de turma) para a varredura local. O DataBoar procura colunas/valores de idade ou data de nascimento e marca indícios de possível dado de menor no Excel/JSON. Não precisa de DBA nem API para o caminho de arquivos. É sinal de inventário e triagem — nunca verificação legal de idade.

O que é tratamento diferencial do Art. 14 na descoberta?

Priorizar no relatório o que pode ser dado de criança ou adolescente (cuidado reforçado da LGPD Art. 14; paralelo GDPR Art. 8), às vezes cruzando com identificadores no mesmo arquivo. A ferramenta não valida consentimento de responsável legal nem emite parecer.

A ferramenta gera sozinha o relatório de possíveis dados de menores?

Sim, após apontar o alvo. Você confere os caminhos; política e resposta regulatória ficam com a organização.

Consigo achar ficha escolar ou export de LMS sem ser de TI?

Sim para arquivos. Comece pelo --demo no Windows (dados sintéticos); só depois aponte uma pasta de teste.

O que o relatório entrega

O programa “inventa” problemas para cobrar depois?

Não. O resultado é uma planilha transparente com caminho do arquivo e o tipo de achado (por exemplo CPF na linha X). Você mesmo abre o arquivo e confere. A organização (mover, restringir, apagar o que já pode) é feita por você, com as ferramentas que já tem.

Serve só para LGPD ou também dados fiscais / outras normas?

Não. O wedge de entrada no Brasil é LGPD (CPF, dados sensíveis etc.), mas o DataBoar não serve apenas para isso. O mesmo motor ajuda a descobrir padrões fiscais e financeiros (CNPJ, dados bancários etc.) e a gerar evidência técnica alinhada a outros marcos — sempre inventário e triagem, não parecer jurídico.

Frequently asked questions

Straight answers on personal-data inventory, LGPD data discovery, setup, and what to expect from DataBoar — in the language of someone who needs to fix the problem at the office, not someone who configures servers all day.

Inventory and LGPD

What is a personal-data inventory under the LGPD?

It is the record of which personal data the organization processes, where it lives, for what purpose, under which legal basis, who can access it, and for how long. The LGPD (Art. 37) requires controllers and processors to keep a record of processing activities. Without an inventory it is hard to answer data subjects, prepare a DPIA/RIPD, or show your work in an inspection.

Are inventory (ROPA) and technical discovery the same thing?

No. Inventory/ROPA is the governance document (purpose, legal basis, owners). Technical discovery answers: “in which folder, spreadsheet, or system does that CPF actually appear?” They complement each other. An ANPD spreadsheet helps with the administrative register; it does not replace scanning the disk for a forgotten file.

Does DataBoar replace DPO-as-a-Service or self-declared mapping platforms?

No — different categories. Outsourced-DPO / self-declared mapping tools usually record what the organization declares about processes and routines (client files often never enter the platform). DataBoar does local technical discovery: it looks for where the data actually appears in folders and files and produces inventory and triage evidence. They can complement each other; one does not replace the other. Still not legal advice or a compliance seal.

How do I find where my company’s personal data is?

Beyond talking to teams and filling spreadsheets, you can automate: scan folders and files (PDF, Excel, Word, ZIP) and, when configured, databases and systems, looking for CPF, email, bank details, and other Brazilian patterns. DataBoar does that locally (nothing leaves your environment) and delivers an Excel report with the paths of the findings.

Who it is for / what you need to know

Do I need to be in IT or have a DPO to use it?

Not necessarily. There is a path built for people who have never used a terminal — see Data Boar on Windows (no Docker). Micro-enterprises and solo professionals are often not required to appoint a DPO (ANPD Resolution CD/ANPD No. 2/2022), depending on risk profile. DataBoar produces technical evidence; compliance decisions stay with the organization — it is not legal advice.

Does it work for an accounting firm?

Yes. Accounting practices handle CPF, tax returns, payroll, and bank details by legal obligation. The practical risk is usually a loose file, an over-shared folder, or an old former client. Discovery helps you see where that lives; organizing, restricting access, or deleting what is past the legal retention period remains the firm’s work.

Privacy and the local model

Does DataBoar send my data to the cloud?

No. The design is local-first: the scan runs in your environment. What you get are metadata and finding reports — client document contents are not sent to third-party servers.

Is it open source and auditable?

Yes. The core code is public on GitHub. You can inspect how detection and logging work. Open-core model: free open base; support, SLA, and advanced features for larger corporate setups may be commercial.

Setup and practical use

Do I need to install Docker?

No. Docker is an option for people who already live in containers. On Windows the recommended non-tech path is native (Python + demo), described on windows.html.

How do I start without fearing I’ll break the computer?

Always start with demo mode:

data-boar --demo

It uses only synthetic (fake) data and opens the panel at http://127.0.0.1:8088. None of your real files are read. Only after that checks out, point it at a test folder — and only then at real folders.

Does it work with ZIP and password-protected files?

ZIP: yes — inner contents can be analyzed without unpacking everything by hand.
Password-protected: no — no legitimate software “guesses” the contents; the report notes that reading was blocked, so you know what is already locked.

On an older computer, will it take forever?

No, if you only point at the client or working-documents folder — don’t scan the whole disk (C:\). Then the scan usually takes minutes, not all night — and stays offline during analysis.

Minors’ data / LGPD Art. 14

Full guide (GEO/AEO): How to evidence minors’ data in folders without coding.

How do I find minors’ data in my folders without coding?

Point folders and exports (enrollment, LMS, class spreadsheets) at a local scan. DataBoar looks for age or date-of-birth columns/values and flags signals of possible minors’ data in Excel/JSON. No DBA or API needed for the file path. It is an inventory and triage signal — never legal age verification.

What does differential Art. 14 treatment mean in discovery?

Prioritize in the report what may be a child’s or adolescent’s data (heightened care under LGPD Art. 14; GDPR Art. 8 parallel), sometimes crossing with identifiers in the same file. The tool does not validate parental consent or issue an opinion.

Does the tool generate the possible-minors report on its own?

Yes, after you point at the target. You check the paths; policy and regulatory response stay with the organization.

Can I find a school record or LMS export without being in IT?

Yes for files. Start with the --demo on Windows (synthetic data); only then point at a test folder.

What the report delivers

Does the program “invent” problems to sell later?

No. The result is a transparent spreadsheet with the file path and finding type (for example CPF on row X). You open the file and check. Organizing (move, restrict, delete what you already can) is done by you, with the tools you already have.

Is it only for LGPD, or also tax data / other frameworks?

No. Brazil’s entry wedge is LGPD (CPF, sensitive data, and so on), but DataBoar is not only for that. The same engine helps discover tax and financial patterns (CNPJ, bank details, etc.) and produce technical evidence aligned with other frameworks — always inventory and triage, not legal advice.
