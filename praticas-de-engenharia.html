Quatro princípios

Cada um existe por causa de um incidente real do setor — não é teoria.

Fail-closed por padrão

Quando uma condição de segurança não pode ser verificada, o sistema nega a operação — nunca assume que está tudo bem. O portão de validação local tem que fechar 100% verde antes de qualquer código subir; nada é liberado só "na confiança do CI remoto". Ver a política de segurança em docs/SECURITY.md.

Dependência travada, não seguida às cegas

Toda dependência de CI fica travada numa versão exata (SHA), nunca numa tag flutuante — e uma versão nova publicada não é puxada automaticamente: ela espera um período de quarentena antes de entrar, dando tempo pra vulnerabilidade recém-descoberta aparecer antes de nós puxarmos. Configuração real, pública, auditável: .github/dependabot.yml.

Integridade verificada, não presumida

Antes de confiar num artefato — um pacote publicado, um binário, a própria ferramenta de build — a integridade dele é conferida primeiro: hash e assinatura, não confiança implícita. É o mesmo princípio por trás do digest de build e do manifesto assinado que publicamos em cada release: docs/RELEASE_INTEGRITY.md.

Metadado primeiro

O que importa pra descoberta é o quê, onde e em que forma — não o dado bruto em si, e não a velocidade de processá-lo. A varredura padrão (o que chamamos de Data Sniffing no glossário) produz achados de metadado, com amostragem limitada e sem exfiltrar o conteúdo. Ver a definição formal: docs/GLOSSARY.md.

Não é caixa-preta.

O núcleo é open-core (BSD-3): audite você mesmo, em vez de confiar numa página de marketing.

Four principles

Each one exists because of a real industry incident — not theory.

Fail-closed by default

When a security condition can't be verified, the system denies the operation — it never assumes things are fine. The local validation gate has to close 100% green before any code goes up; nothing ships on "trust the remote CI" alone. See the security policy at docs/SECURITY.md.

Dependencies pinned, not followed blindly

Every CI dependency is pinned to an exact version (SHA), never a floating tag — and a newly published release isn't pulled in automatically: it sits in a quarantine period first, giving a freshly discovered vulnerability time to surface before we pull it. Real, public, auditable config: .github/dependabot.yml.

Integrity verified, not assumed

Before trusting an artifact — a published package, a binary, the build tooling itself — its integrity is checked first: hash and signature, not implicit trust. Same principle behind the build digest and the signed manifest we publish with every release: docs/RELEASE_INTEGRITY.md.

Metadata first

What matters for discovery is what, where, and in what shape — not the raw data itself, and not how fast it's processed. The default scan (what the glossary calls Data Sniffing) produces metadata-only findings, with bounded sampling and no content exfiltration. See the formal definition: docs/GLOSSARY.md.

Not a black box.

The core is open-core (BSD-3): audit it yourself, instead of trusting a marketing page.
