Open-core & method

Open by design. Verifiable by nature.

You can audit how DataBoar behaves — you don’t have to trust a black box.

DataBoar’s core is open-core (BSD-3), detection is deterministic, and every finding is reproducible. Our value is not a patented secret: it is execution, integration, and trust. We publish the recipe and charge for the service.

Why open

Trust is built with transparency, not marketing — especially in compliance.

Open-core (BSD-3)

The core is free: read it, audit it, and run it where you want — including air-gapped. Permissive license, no lock-in.

No software patents

Copyright, subscription, and patents are different things. We hold copyright and charge for subscription — we do not patent the method. Patenting an algorithm is like patenting a book chapter.

Deterministic AI, not LLM

ML (Random Forest + TF-IDF), Deep Learning, and a Clojure sidecar. Real AI — reproducible, verifiable, and without LLMs, generative models, or agentic stacks. No hallucination, no black box. For extensions, the core emits a metadata manifest (no raw values) for external sidecar modules, kept separate from the open-core.

Every finding is checkable

Rules, validation (check digits, Luhn), and normative references on each result. You inspect the evidence — you do not trust an opaque score.

An honest primer: AI ≠ LLM

AI is the umbrella. LLM, generative, and agentic systems are only one branch of it.

What we use

Specialized ML and DL models, heuristics, and a deterministic Clojure sidecar — the branch of AI that is reproducible and auditable. Strong where it matters, predictable always.

What we do NOT use on the critical path

No LLM decides whether your data is sensitive. No generative models, no hallucination, no third-party cloud dependency for classification. Non-injectability by target content becomes a security property, not only a reproducibility one.

Global by default

Real multi-locale and multi-encoding: bilingual at minimum, any language in minutes. The scanner understands your data wherever your organization operates.

Why this matters for audits

Deterministic means an auditor (or you) can reproduce the same result under the same versions, configuration, and inputs. An LLM classifier can’t guarantee that: it changes its answer and doesn’t show its work. Reproducible evidence is what holds up under scrutiny.

What we give back

Generous open-core: the method is public and the community benefits.

Ported wheelhouse

We publish wheels for platforms upstream does not cover — no-AVX, musl, older hardware, free-threaded — for teams that run where the big stacks will not go. Ready-made wheels exist for special cases: CPUs without AVX (glibc and musl) and, as a lab wheelhouse with SHA256 (not a supported channel), Haiku R1/beta6, FreeBSD 15.1, NetBSD 11.1 and OpenBSD 8.0 — see the index, the Releases and the per-OS install notes. illumos has no wheels yet.

Published method

Patterns, validations, and decisions live in ADRs and open source — auditable by anyone, no NDA required to understand how it works.

Open docs and glossary

Bilingual documentation (pt-BR/en-US), a glossary aligning engineering, compliance, and procurement, ADRs, and even a field LGPD witness report — all open, no NDA to understand it.

Fixes back upstream

When we fix a bug or package something that was missing, we send it back to the projects we rely on — adopted orphan packages, submitted patches. The ecosystem that supports us gets better.

Ready-made compliance samples

Open, reusable framework configs — LGPD, GDPR, CCPA, GLBA, plus samples for UK/EU GDPR, PIPEDA, POPIA, APPI, and PCI-DSS. Tune your profile without starting from scratch.

Lab wheelhouse: install by OS

Recipe validated in the lab (VM), with published SHA256. Not a supported channel.

The index is exclusive: use --index-url (never --extra-index-url, which merges PyPI). The system pip must report the wheel's platform tag.

  • FreeBSD 15.1 (Python 3.12; the tag carries patch p6): pip install --index-url https://databoar.com.br/simple/ --only-binary=:all: numpy
  • NetBSD 11.1 (Python 3.12): pip install --index-url https://databoar.com.br/simple/ --only-binary=:all: numpy
  • OpenBSD 8.0 (Python 3.14): pip install --index-url https://databoar.com.br/simple/ --only-binary=:all: pymongo
  • Haiku R1/beta6 (Python 3.14): the index does not resolve, because GitHub rewrites the ~ in the tag to .. Download the files from the Release, restore the ~ in the names, check with sha256sum -c SHA256SUMS and use pip install --no-index --find-links .. Step by step in the inventory.

Limits: the sets are partial (what is missing, such as scipy on NetBSD and OpenBSD, does not resolve through the index); OpenBSD cryptography is not portable; NetBSD wheels may link libraries of the build host; illumos has no wheels. The test was pip resolution against the index, not an install on the VMs.

Unix way: each tool does one thing — and proves it

Against the monolith that does everything and asks for trust: small, composable, verifiable tools.

One scope per piece

The boar does one thing very well: discover and prove where personal data lives — with evidence, without retaining the data. Masking, tokenization, and data-subject rights come from plugins and composable tools, each with a small verifiable scope — not a black box that does everything.

You choose where it runs

Designed for on-prem on min-spec, air-gapped when industry and regulation require it, in your cloud (multi-vendor, multi-zone), or as our SaaS. Explicit opt-in — by contract, by audience, by any regulation.

Not a cheap clone

We are not the discount version of an enterprise suite. We are another category: open, deterministic, verifiable — and designed to run where heavy platforms will not. Honest scope is the product.

Outputs like a pipe, fits any pipeline

Machine-readable output (JSON, Excel, evidence manifests), honest exit codes, config-driven. The boar plugs into your CI, your SIEM, your GRC — it doesn’t force you to live inside our UI.

The beasts: what they do today × what's next

Sister tools of Data Boar, one scope each. Here is what the code and docs already prove — and what is still a plan. None has a published release; anything simulated or demo-only is labeled.

Sage Remora (Sage)

Today: reads only the Boar findings manifest — metadata, never the value. It infers re-identification risk (indirect identifiers, cross-table linkage), decides policy (what to tokenize, who may see what) and asks for confirmation when it needs more evidence. It refuses a manifest that carries a raw value and executes nothing on the content. Every decision carries the reasoning behind it.

Label: the current rules are illustrative proof-of-concept content, not a validated ruleset.

Next: a memory of what was decided over time (planned; today each run reads one manifest and answers).

Faithful Ferret (Ferret)

Today: runs only with an explicit per-dispatch grant, limited to the authorized columns; no grant, no run. Over the rows it receives, it measures how unique the records are (k-anonymity) and returns the measurement as evidence, with its limitations — not as a verdict. It does not connect to a database: it receives rows already delivered. It is ephemeral, logs what it did and refuses an output that contains the value.

Label: exercised so far only with synthetic data, in development mode; thresholds are proof-of-concept, not a certified methodology.

Next: more missions (draft today), a time limit per dispatch (not enforced yet), a destruction attestation signed by the dispatcher (unsigned today) and record-aligned rows straight from the Boar (still a proposal).

Stealthy Stoat (Stoat)

Today: swaps the sensitive value for a token in place, without exfiltrating it. The software rung uses FF1 (NIST SP 800-38G) in Rust, checked against the NIST sample vectors; it is not CAVP/FIPS validated and it is not an HSM. Values too short for the cipher are refused.

Label: runs as a demo, with synthetic values only. The HSM client uses a simulated transport: it has never been tested against a real HSM. TPM and KMS are interfaces only, not wired yet.

Next: a real HSM with measured throughput (there is no measured number today) and CAVP/FIPS validation — planned, no date.

Keen Platypus (Platypus)

Today: a local DevSecOps assistant: authorized recon and vulnerability scanning, code and supply-chain review, and pentest correlation in phase 1 only (recon and correlation — not a full pentest). Code review has a deterministic tier that closes with no call to a language model; when a model is used, it is the user's own, and a model alone never confirms a finding. It is a separate tool: Data Boar stays LLM-free on the path that decides what is sensitive data.

Label: the code module's automated tests use scanner stand-ins, and the limits are declared in the project documentation.

Next: live attack confirmation, a red → blue bridge, SARIF export to GRC tools and integration with the Ferret (all planned, none of it exists today); a polyglot rewrite is in progress and incomplete.

Order in the pipe: Boar → Sage → Ferret; the Sage also feeds the Stoat (boar | sage > stoat). Outputs are technical evidence for a person to decide on, not a verdict. The repositories are private.
