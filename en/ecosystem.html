Composition ecosystem

An ecosystem of independent plugins.

Bestials connected via SDK. No monolithic runtime. Explicit superpowers.

The Data Boar Ecosystem is an architecture of composition: each Bestial is an independent plugin/sidecar that communicates via SDK contract. Choose the tools you need — you're not forced to use them all.

View the code on GitHub → Book a demo

Overview of the architecture

This is not a monolithic product. It's an ecosystem of separate plugins.

Composable by design

Each Bestial is an independent plugin/sidecar with defined scope. They connect via SDK — not via internal code calls. Use only the tools you need.

Explicit superpowers

Each Bestial has a unique, documented responsibility. You know exactly what each plugin does — and what it does NOT do.

Clear boundaries

Data limits, authorization, retention and egress are defined by contract. No plugin decides on data that was not explicitly authorized.

Auditable by design

All plugins follow the same contract pattern. You can audit each one's behavior separately.

The Bestials: Ecosystem superpowers

Each has a clear mission. None is mandatory.

Sage Remora (Sage)

Power: Re-identification risk analysis without touching data. Reads finding manifests and infers risk of indirect identifier cross-over.

Maturity: Development/PoC

Contract: L1 Manifest SDK

Faithful Ferret (Ferret)

Power: Measures k-anonymity over authorized data and flags groups below the configured k threshold. Reduces re-identification risk from indirect-identifier linkage — it does not replace a privacy risk assessment and does not cover homogeneity or background-knowledge attacks.

Maturity: Demo/PoC

Contract: L3 Transformed SDK

Stealthy Stoat (Stoat)

Power: FF1 tokenization (NIST SP 800-38G). Replaces sensitive values with controlled reversible tokens.

Maturity: Demo/PoC

Contract: L3 Transformed SDK

Keen Platypus (Platypus)

Power: Local DevSecOps: vulnerability scanning and code. Detects supply chain risks.

Maturity: Development

Contract: SDK

Typical flow: Boar → Sage → Ferret. Sage also feeds Stoat (boar | sage > stoat).

How plugins communicate

SDK as single contract for all plugins.

Finding manifest (L1)

First tier: structured metadata about what was found. Never raw values.

Governed transformation (L3)

Third tier: transformed data with explicit permission scope. Always auditable.

Verifiable outputs

Each plugin produces technical evidence for a person to decide — not an automated verdict.

Read the code before you trust it.

It is open-core: audit it, run it locally, and see why the evidence is reproducible.
